# content — stage contract (final page production)

Method: MIRENA Operating Rules §4–§9 and the writer persona govern the craft —
semantic vocabulary, cohesion, information gain, NLP-friendly structure. That
is your space; use it fully. This contract fixes the rails.

Input truth: the approved canonical brief ONLY. The brief's semantic territory
is a hard boundary — no entities or intents it excluded, no expansion into
sibling pages' owns.

Output: one artifact with the packet's frontmatter — the frontmatter block
additionally carries `slug`, `seo_title`, and `meta_description` — followed by
the complete page as SIMPLE HTML (the production format): `<h1>` once, `<h2>`/
`<h3>` sections per the brief's plan, `<p>`, `<ul>`/`<ol>`, `<table>` where the
brief calls for one, real `<a href="">` internal links exactly per the brief's
link plan (descriptive anchors; site-relative URLs from the approved map),
authority outlinks per Operating Rules §5, FAQ as an `<h2>` section with
`<h3>` questions (only the triage-assigned FAQ items). No `<html>`, `<head>`,
`<body>` wrappers, no inline CSS or scripts, no markdown syntax in the body.

Hard rails (machine-scanned): nothing from the never-claim patterns in
claims-compliance; nothing from the banned phrases in voice-tone; every
answer_with_correction query answered with the corrective fact; PAA-targeted
sections lead with a direct answer in the first ~40 words (extraction-ready);
all numbers either from the inputs or written as modeled estimates with the
required qualifiers; [ASSUMPTION]/[REQUIRES CONFIRMATION] markers survive into
the draft wherever truth is missing — never papered over.

Acceptance: Operating Rules §9 final acceptance check + coverage of every
brief obligation + Document Usage Check.
